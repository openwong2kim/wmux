### Fixed

- **Reading a pane's text no longer waits behind other panes while many of them write at full speed.** Each read used to parse the pane's whole buffer in a queue shared by every pane, so with 20 busy panes a 100-row read took about 4 s (12 s at p95). A read now parses only the newest output when that gives the same rows, falling back to the whole buffer otherwise, and a long parse gives way to other work more often. The same read now takes about 50 ms. A 5000-row read under that load is still slow, about 9 s, because of the size of its reply. Reads that gate an action still read the whole buffer. (#3542)
