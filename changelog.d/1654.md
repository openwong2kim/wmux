### Fixed

- **Transcript images and videos now stay inside their folder on Windows.**
  When the phone asked for an image or video named in a transcript, the daemon
  checked that the file was inside the pane's folder and then opened it. It
  relied on two file-open flags to catch a link swapped in between the check
  and the open, and those flags do not exist on Windows. There, a directory
  on the path could be swapped for a junction in that window, and the file
  outside the folder was sent. Both routes now re-check what they actually
  opened: it must be a regular file, the path must still name it, and the path
  must still resolve inside the folder. Anything else gets the same "not found"
  as a missing file. The re-check also closes the directory-swap case on macOS
  and Linux, which the flags never covered there. (#1654)
