### Security

- **A bot's skill reaches its workers with only the front matter you approved.**
  A skill's front matter (the block between its `---` lines) could be read
  one way by wmux and another way by Claude Code: an indented `---` ended it
  for wmux but not for some Claude Code readers. The lines after it reached a
  worker's copy of the skill as settings, not text, and the approval card
  showed them as part of the procedure. wmux now reads a skill only when
  both agree: the front matter starts on line 1 and ends at the first line
  that is exactly `---`, and holds nothing but its name, description and
  version. Every other skill is refused. A worker's copy is written fresh
  from those three fields instead of copied byte for byte, and the approval
  card shows them apart from the procedure, exactly as Claude Code will read
  them. Skill and reference names can no longer be a Windows device name
  such as `con` or `aux.md`. An approved skill that does not pass the
  stricter check shows as changed in the bot's profile and stops loading
  until the bot proposes it again. Follows up #2288. (#2351)
