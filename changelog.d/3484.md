### Fixed

- **The MCP process no longer keeps a copy of every browser response it sees.** Network capture used to read each textual response body as it arrived, and Playwright held on to that copy for as long as the page stayed open. A session that used browser tools heavily could push the MCP process past 700MB over a couple of days, and with the shared MCP broker one process carries every session's browsing. Now only small XHR and fetch bodies (up to 256KB each, 4MB in total) are kept, as plain text, so they can still be read after the page navigates away. Other bodies stay in Chrome, which keeps only a bounded amount, and `browser_response_body` fetches one only when you ask for it. If Chrome has already let it go, the tool says the body is no longer available. Requests made inside cross-site iframes are still captured, though a request an iframe makes in its first moments can be missed; requests from web workers are not captured. Every 5 minutes the MCP process also logs its memory use to stderr, and it warns when external memory passes 300MB. (#3484)
