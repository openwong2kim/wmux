### Fixed

- **A pane no longer stays "complete" through its next turn (local mode).** In
  local mode the activity cycle that re-arms the `running` status only reset
  after five seconds of complete byte silence — which a TUI painting a live
  elapsed-time counter never reaches, because every repaint reschedules the
  idle timer. So the `complete` written when a turn ended survived the whole
  next turn, and a turn the agent started by itself (a background task
  finishing and the agent resuming, with no submitted input to open a new
  cycle) never reported running at all. Every authoritative turn end — the
  Stop hook, an awaiting-input hook, and an un-vetoed detector completion —
  now re-arms the cycle, threshold-based, so the next real burst of output
  reports running while idle chrome still cannot. In daemon mode (the packaged
  Windows build) the same edge re-arms the cycle immediately instead of up to
  five seconds later and clears a stale idle timer; byte activity alone still
  cannot flip a settled pane back to running there — an authoritative running
  edge or submitted input reopens that gate, by design.
- **A Claude Code pane reports that it is working again.** Nothing in the
  detector produced a `running` status for any agent — the only such signal was
  a one-shot fired when an agent was first recognised — so a turn the agent
  started by itself had no way to say so, and the pane kept the previous turn's
  status. Claude's `esc to interrupt` hint, which exists only while a response
  is in flight, is now that signal. It deliberately abstains when a repaint
  merges the hint with the permanent mode footer, so a finished pane is never
  talked back into running; the next repaint carries the hint alone.
