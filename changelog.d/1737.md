### Added

- **A pane that starts a fan-out hears back when its workers finish.** When the workspace has no orchestrator (agent mode Off, the default), a worker's stop used to be only recorded for an orchestrator that never started, so the agent that ran `fanout_start` was never told. Now that pane gets one line, `[wmux] fan-out task <id> updated — channel_mission_list`, once its agent is idle; several tasks finishing together share one line. Only the pane that started the fan-out is told, only when it is still open and running an agent, and the line carries no worker output. Failed worker turns count too; a worker waiting for input does not. (#1737)
