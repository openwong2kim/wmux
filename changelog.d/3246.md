### Fixed

- **A file that was busy for a moment no longer rolls your wmux state back.** On Windows, antivirus or another process can hold a state file just as wmux reads it. wmux took that failed read as a reason to use an older backup, or nothing at all, and the next save wrote that over the good file. It now waits briefly and tries again. If the file still can't be read, wmux reports that and refuses to overwrite the file until a read gets through. (#3246)
- **A damaged state file can no longer replace its good backup.** Saving moved the current file over its backup without checking it. Now only a file that passes validation becomes the backup, and a damaged one is set aside in `corrupted/`. (#3246)
- **Falling back to a backup now shows in `wmux doctor`.** Backup fallbacks, failed reads and set-aside files are written to the main and daemon logs in the form the doctor counts. (#3246)
