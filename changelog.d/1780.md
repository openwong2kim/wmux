### Fixed

- **Codex behind the shared background server gets its own pane identity for A2A.** A `codex` running on the shared app-server used to fail `a2a_whoami` and `send_message` with "Workspace identity unknown", or could act as the pane that started the server. The wmux MCP server now reads the conversation id Codex sends with every tool call and resolves it to the pane that owns that conversation, live, on every call. If no open pane owns it, the error says why instead of guessing. Claude Code, `codex --no-daemon` and other MCP clients are unchanged. (#1778, #1780)
