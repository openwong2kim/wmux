### Fixed

- **Korean and other multi-byte text no longer turns into `�` in MCP tool
  results.** When a reply from wmux arrived in more than one piece and a
  character was split between two pieces, both halves came out as the
  replacement character. Large replies are also read in linear time now.
  (#3486)
- **`browser_console` no longer makes the MCP process grow while a page logs
  objects.** Before, every argument of every console message stayed in memory
  until the page closed: a page logging an object 3000 times grew the process
  by about 30 MB. Console messages read the same as before, with these
  differences:
  - A BigInt argument prints as `12n` instead of `undefined`.
  - A line a cross-site iframe logged before wmux reached it shows objects by
    name (`Object`) instead of their contents.
  - Over wmux's pipe relay, a dedicated worker's console messages are not
    captured, the same as its network requests. Its uncaught exceptions still
    are.
  - Console capture shares network capture's reach: the first 16 cross-site
    iframes on a page, and no workers started inside a cross-site iframe.
  (#3486)
