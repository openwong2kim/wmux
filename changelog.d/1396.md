### Fixed

- **A paired phone can no longer reach the orchestrator's own pane.** Every
  route that takes a pane id from the caller — the terminal stream, typing,
  the diff and command lists, resize and pane close — resolved the pane by
  existence alone. A phone that learned the orchestrator brain pane's id, which
  is guessable by prefix, could stream its raw terminal output, type into it,
  read its diff and close it, even though that pane is deliberately hidden from
  the phone's pane list. The brain pane is now refused on all of those for a
  paired device, answering exactly as it does for a pane that does not exist so
  the error cannot confirm the id. Nothing changes for the operator token,
  which still drives the orchestrator's pane from the desk as before. (#1396)

- **The orchestrator's alerts and notifications stay off paired phones.** A
  critical-command alert or a desktop notification raised inside the
  orchestrator's own pane was broadcast to every connected device, and kept in
  the replayable event window, carrying the pane id along with text the pane
  itself wrote — the matched command line, or a notification title and body.
  Those events are now withheld at the source, so the id and the content never
  reach a phone in the first place. (#1396)
