### Added

- **Contain the agents in your own panes with the worker fence.** The worker fence used to protect only a bot's unattended workers. Now any terminal tab can opt into it, from the pane menu (**Contain agents**) or, for new terminals, from the workspace profile. It is off by default. Agents wmux starts in a fenced tab run inside the same fence: Bash runs in the OS sandbox (macOS sandbox-exec, Linux bubblewrap), claude's write tools are kept inside the tab's folder, and credential files can't be read. This covers launches, resumes and the F7/F8 keybindings. A claude you type into the shell yourself is not fenced. It works with Claude Code only for now, and a Codex launch in a fenced tab is refused. As with fenced bot workers, your user settings' hooks, enabledPlugins and statusLine are not loaded; env, model and apiKeyHelper are carried. A launch is refused with the reason instead of starting unfenced when:
  - only a weaker fence could run (no OS sandbox, a WSL pane, Windows);
  - the fence's self-test failed;
  - the folder is your home folder, holds a credential path, or is inside one.
  - the folder's own `.claude` settings set hooks, helpers or env, which would run outside the fence.

  A muted **Fenced** chip in the tab strip shows the state. **Fence: next launch** means a running agent keeps the state it started with, and **Fence refused** names the reason. (#3482)
