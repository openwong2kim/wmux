### Added

- **Protected browser profiles can run on Chrome's debugging pipe.** With
  `WMUX_CHROME_TRANSPORT=auto`, a protected profile starts on the pipe and the
  rest stay on the DevTools port. On the pipe, agents see and drive only web
  pages (`http`, `https`, `data:` and blank pages). A `chrome://` tab the user
  opens is hidden from them, and no debugging port opens. If that Chrome
  writes a debugging-port file, wmux closes it. A protected start that fails
  says why and never falls back to the port. `WMUX_CHROME_TRANSPORT=port`
  moves a protected profile to the port only when `protectedPortTransport` is
  set in `browser-backend.json`. `wmux browser session status` shows the
  transport. The default is still the port for every profile. (#3456)

### Changed

- **A protected pane no longer receives a CDP port or WebSocket endpoint**
  from `browser.cdp.info`, on either transport. On the default port transport
  its browser tools use the RPC lane; a tool without that fallback now reports
  that no usable CDP endpoint was disclosed. Before, the pane got the port.
  (#3456)

### Fixed

- **A download in another browser context is cancelled on a protected
  profile.** Before, a download in a context other than the default one, such
  as an off-the-record window, could stay in progress after it was cancelled.
  (#3456)
