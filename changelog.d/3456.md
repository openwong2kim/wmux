### Changed

- **Protected browser profiles now run on Chrome's debugging pipe.** Before,
  a protected profile ran on the DevTools port like every other profile.
  Unprotected profiles stay on the port.
  - Outside tools connect through wmux's relay grant, and see and drive only
    web pages (`http`, `https`, `data:` and blank pages). A `chrome://` tab
    the user opens is hidden from them.
  - No debugging port opens. If one does, wmux closes that Chrome and says why.
  - A protected start that fails says why and never falls back to the port.
  - `browser.cdp.info` no longer gives a protected pane a CDP port or
    WebSocket endpoint.
  - The operator setting `protectedPortTransport: true` in
    `browser-backend.json` puts a protected profile on the port, with a
    warning.
  - `wmux browser session status` shows the transport. (#3456)

### Fixed

- **A download in another browser context is cancelled on a protected
  profile.** Before, a download in a context other than the default one, such
  as an off-the-record window, could stay in progress after it was cancelled.
  (#3456)
