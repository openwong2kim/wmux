### Fixed

- **A pane's working directory follows `cd` again.** On Windows, every terminal's
  tracked directory was frozen at whatever it started in: `cd` into a project and
  the pane still reported your home folder, for the rest of the session. The tab
  tooltip and the workspace "Working directories" menu showed the wrong path, and
  anything that reads a pane's directory acted on the stale one — fan-out, in
  particular, refused to start with "the calling terminal's directory is not
  inside a git repository" even while the pane sat in a repo. The workspace-level
  path did update, which is why this stayed invisible in normal use.
